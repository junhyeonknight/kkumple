# 꿈플 자동 업데이트 2.2.0

AutoCAD가 꿈플을 불러오기 전에 업데이트를 확인하는 별도 점검기입니다. 현재 꿈플 본체는 2.0.3이며, 이 프로젝트는 자동 업데이트 기능을 추가합니다.

## 동작

`AutoCAD 시작 → 서명된 종료 상태 확인 → 업데이트 확인 → 새 버전 자동 설치 → 기존 LISP 로더 → 꿈플 기능`

새 버전이 없으면 설치 없이 기존 꿈플을 불러옵니다. 새 버전이 있으면 전자서명, CAD 계열, 파일 크기와 SHA-256을 확인한 뒤 자동 설치합니다. 확인한 필수 업데이트를 건너뛰는 버튼은 없습니다. 같은 CAD 세션에서 도면을 추가로 열 때는 승인 결과를 재사용합니다.

**기본값은 온라인 확인 필수입니다.** 인터넷·서명 확인·설치가 실패하면 그 시작에서는 꿈플을 불러오지 않습니다. AutoCAD와 도면은 계속 사용할 수 있습니다. 운영자의 유효한 종료 신호가 있어도 업데이트와 꿈플 로드를 중단합니다. 이미 열려 있는 CAD를 강제로 종료하거나 로드된 기능을 강제로 언로드하지 않습니다.

## 설치 준비 상태

코드와 실행파일, 기존 운영 키로 서명한 2.0.3 기준 파일을 준비했습니다. 사용자 승인 후 GitHub `main`의 `update.json` 게시를 완료했고, 공개 원문 HTTP 200·RSA 서명·준비 파일과의 일치를 확인했습니다. 온라인 기준 버전은 **2.0.3**이며 다운로드 항목은 아직 없습니다.

설치할 때는 다음 순서로 진행합니다.

1. 꿈플 본체 2.0.3을 먼저 설치하고 AutoCAD를 종료합니다.
2. 기존 서비스 종료 점검기를 사용한다면, 포함된 `서비스종료점검기/자동점검-설치.cmd`로 2.2.0 버전을 다시 설치합니다. 이전 버전의 점검기는 파일 동시 변경 보호를 지원하지 않아 함께 사용할 수 없습니다.
3. `자동업데이트-설치.cmd`를 실행하여 내용을 읽고 체크한 다음 설치합니다.
4. 다음 AutoCAD 시작부터 점검기를 거쳐 꿈플을 불러옵니다.

이 작업에서는 실행 중인 CAD의 설치 번들을 변경하지 않았으며, 운영용 점검기를 현재 PC에 설치하지 않았습니다. 다른 PC에는 이 초기 연결 설치를 한 번씩 수행해야 합니다. 기존 설치본에 점검기가 없는 상태에서는 온라인 파일만 올려도 새 기능이 저절로 추가되지 않습니다.

## 설치 위치와 제거

- 점검기: `%LOCALAPPDATA%\Kkumple\Updater\Kkumple.Updater.exe`
- 설정: 같은 폴더의 `updater-config.json`
- 기록: 같은 폴더의 `updater.log`, `install-state.json`
- 시작 연결: 꿈플 번들의 `PackageContents.xml`과 `Contents/Loaders/kkumple-update-gate-*.lsp`
- 이전 버전 백업: 번들의 `Contents/Versions/.kkupd-backup-<식별자>`

AutoCAD를 종료한 뒤 `자동업데이트-제거.cmd`를 실행하면 원래 LISP 로더 연결로 복원합니다. 본체·도면·로그·복구용 백업과 점검기 파일은 보존합니다. 설치 이후 다른 프로그램이 시작 설정이나 점검 LISP를 수정했다면 자동 덮어쓰기/제거를 거부합니다.

꿈플 본체의 원래 설치기를 다시 실행하여 시작 설정을 새로 만든 경우에는 자동 업데이트 설치도 다시 실행해 연결합니다.

## 파일 보호와 복구

원래 시작 LISP와 기능 DLL을 패치하지 않습니다. 시작 설정 앞에 별도 LISP 점검기를 연결하고, 업데이트 때는 해당 CAD 계열의 `Contents/Versions/<계열>` 파일을 새 폴더에 준비한 뒤 교체합니다.

현재 사용하는 프로그램 폴더 전체를 복사해 기존 파일을 보존하고 새 패키지를 덧씌웁니다. `.dwg`, `.dxf`, `.dwt`, `.dws`, `.bak`, `.ini`, `.cfg`, `.settings`는 업데이트 패키지가 덮어쓸 수 없습니다. 패키지에 없는 파일도 보존합니다. 다른 개인 자료는 프로그램 폴더 밖에 보관하세요.

연결 폴더·심볼릭 링크, 폴더 밖 ZIP 경로, 이름 중복, 과도한 압축 해제 크기·항목 수를 거부합니다. 다른 CAD가 파일을 사용 중이면 교체 전에 중단합니다. 교체 도중 실패하면 원래 프로그램과 시작 설정·설치 기록을 복원하며, 중단 기록이 남은 경우 다음 점검에서 복구합니다. 종료 점검기 2.2.0과는 같은 전역 잠금을 사용합니다.

백업과 실패한 준비 폴더는 데이터 손실 방지를 위해 남겨 둡니다. 반복 업데이트 후에는 디스크 사용량을 확인하세요. 같은 사용자 계정의 다른 프로세스가 파일을 악의적으로 바꾸는 상황까지 완전한 격리를 보장하는 기능은 아닙니다.

## 운영자가 새 버전을 배포하는 방법

온라인 주소는 다음 두 개를 사용합니다.

- 업데이트: `https://raw.githubusercontent.com/junhyeonknight/kkumple/main/update.json`
- 종료 상태: `https://raw.githubusercontent.com/junhyeonknight/kkumple/main/status.json`

처음에는 `온라인게시용/2.0.3/update.json`을 저장소 `main` 루트에 게시합니다. 이 파일은 현재 2.0.3을 최신으로 알리며 프로그램 다운로드 항목은 없습니다. 기존 종료 상태 파일은 그대로 둡니다.

이후 실제로 개선한 본체를 준비하면 다음과 같이 새 버전을 만듭니다. 원래 프로그램 설치기와 일치하는, 사용자 자료가 섞이지 않은 깨끗한 새 버전 번들을 사용하세요.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\new-update-release.ps1 `
  -Version 2.0.4 `
  -SourceBundle 'C:\새버전\KkumpleFree.bundle' `
  -BaseUrl 'https://github.com/junhyeonknight/kkumple/releases/download/v2.0.4' `
  -PrivateKey 'C:\운영자보관\privatekey.xml' `
  -OutputDirectory 'C:\배포준비\2.0.4'
```

`2.0.4`와 경로는 예시이며, 실제 새 버전 파일이 있어야 합니다. 도구는 본체 `PackageContents.xml`의 버전과 요청 버전이 같은지 확인합니다. `2010`, `2013`, `2015`, `2025` 계열 폴더별 ZIP과 서명된 `update.json`을 만듭니다. 실제 지원할 CAD 계열의 ZIP을 모두 준비하세요.

**ZIP들을 GitHub Release에 먼저 올리고 다운로드를 확인한 뒤, 마지막으로 `update.json`을 교체**합니다. 새 파일을 같은 버전 번호로 바꾸면 이미 그 버전인 PC에는 다시 설치하지 않으므로 버전을 올려야 합니다. 시작 로더와 본체 설치 UI 자체를 변경하는 배포는 별도 설치본 연동이 필요합니다. 이 자동 업데이트 패키지는 버전 계열의 프로그램·리소스를 갱신합니다.

서명은 기존 운영 개인키로 로컬에서만 수행합니다. 개인키를 클라이언트·배포 ZIP·GitHub에 넣지 않습니다. 기준 파일의 유효기간은 생성 시 기본 1년이며, 만료 전에 새로 서명하여 게시해야 합니다. 최초 2.0.3 기준의 만료 시각은 `2027-11-17T05:11:00Z`입니다.

## 설치 UI 수정

`Updater/Program.cs`의 `SetupForm`에서 제목·문구·크기·색상·로고·체크박스·버튼을 수정하고, `UpdateForm`에서 다운로드 진행 화면을 바꿀 수 있습니다. 고지문은 `GateInstaller.cs`의 `Disclosure`에 있으며 동의 기록에는 해당 문구의 해시가 저장됩니다.

기존 `꿈플.exe` 본체 설치 화면을 바꾸려면 그 프로그램의 소스가 필요합니다. 현재 제공된 본체 폴더에는 실행파일과 안내·검증 자료가 있습니다.

## 빌드와 검증

Windows의 .NET Framework 4.8, C# 5 호환으로 빌드했습니다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

자동 업데이트·연동 115개와 배포 도구 13개, 기존 종료 기능 86개를 검증했습니다. 실제 GUI AutoCAD 재시작을 통한 최종 확인은 남아 있습니다. 설치된 Core Console은 라이선스 오류로 종료되어 해당 검증을 완료하지 못했습니다. 원래 설치기의 연결 해제·재설치 흐름과 다른 CAD 연도도 실제 환경에서 확인해야 합니다. EXE 코드 서명은 수행하지 않았습니다.
