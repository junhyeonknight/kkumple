# 꿈플 자동 업데이트 인수인계

2026-11-17. 사용자 요청: AutoCAD가 꿈플을 시작할 때 확인하고, 새 버전이 없으면 기존 실행, 있으면 자동 설치 후 실행. 백그라운드 작업 유지. 설치 UI는 추후 변경 가능하게 소스 제공.

## 준비된 결과

- `Updater/UpdateCore.cs`: 서명/상태 검증, 버전 비교, HTTPS 다운로드, ZIP 검사, 백업·교체·복구.
- `Updater/GateInstaller.cs`: 별도 LISP 시작 점검 연결, 원래 소스 보존, 설치 기록, 소유권 확인/복원.
- `Updater/Program.cs`: 동의 및 진행 화면, CLI 설치/제거/확인, 전역 잠금과 종료 신호 확인.
- `배포/`: EXE·공개키 설정·더블클릭 설치/제거.
- `tools/new-update-release.ps1`: 실제 새 버전 폴더에서 계열별 ZIP과 서명된 안내 생성.
- `온라인게시용/2.0.3/update.json`: 기존 운영 키로 서명, 클라이언트 공개키 검증 통과, 기준 버전 2.0.3, 패키지 없음.
- 기존 `service-end`도 2.2.0으로 갱신하여 같은 `Global\KkumpleBundle-<경로 해시>` 잠금 사용. 이전 점검기 설치자는 최신본으로 재설치 필요.

## 온라인 게시 완료

대상: 공개 저장소 `junhyeonknight/kkumple`, `main` 루트의 새 `update.json`.
URL: `https://raw.githubusercontent.com/junhyeonknight/kkumple/main/update.json`.
기존 `status.json`은 변경하지 않는다.

연결된 GitHub 앱의 파일 생성은 403으로 거부되어 기존 브라우저의 백그라운드 탭을 사용했다. 자동 승인 검토의 실행 시점 확인 요구에 따라 사용자에게 정확한 게시 대상을 확인받고 커밋했다. 공개 원문은 HTTP 200, 전자서명 유효, 로컬 준비 파일과 일치한다. 파일 블롭 SHA는 9bc89329de9781e490db04efd65397784d8a4377. 게시 완료 후 브라우저 연결이 끊어져 GitHub 연결 도구와 공개 원문에서 결과를 확인했다.

## 실환경 상태와 한계

현재 설치는 `%APPDATA%\Autodesk\ApplicationPlugins\KkumpleFree.bundle`, 본체 2.0.3, 이 PC는 2015 계열. 원래 로더 바이트와 DLL은 수정하지 않았다. 실제 운영용 점검기 연결도 설치하지 않았다. 사용 중인 AutoCAD와 도면을 조작하지 않는다.

본체 실행파일: 사용자가 지정한 `C:\Users\은준현\Downloads\꿈플-2.0.3-원본명령어-검증판\꿈플.exe`. 해당 폴더에는 본체 소스가 없으므로 본체 설치 UI 수정에는 별도 소스가 필요하다. 새 자동 업데이트 UI는 `SetupForm`과 `UpdateForm`에서 수정 가능하다.

업데이트/배포 생성 128개, 기존 기능 86개 검증 통과. GUI CAD 실환경 재시작 검증은 남음. Core Console은 라이선스 오류로 종료했으며 이를 우회하지 않았다. 개인키는 기존 운영 위치에서 로컬 서명만 수행했고 복사·출력하지 않았다.
